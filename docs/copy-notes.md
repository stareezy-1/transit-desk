# Transit Desk copy direction

Applied skill: [copywriting by coreyhaines31/marketingskills](https://skills.sh/coreyhaines31/marketingskills/copywriting), version 2.2.0. The skill and its `references/ai-tells.md` self-check were read directly from the public repository. No global installation was required.

## Brief

Audience: a person inspecting MBTA vehicles, whether by number, destination, route, or trip. Primary action: find a vehicle and inspect its last reported position. Tone: a helpful person at a transit desk; specific, mildly playful, and honest about the feed's limits. This is a working interface, so promotional claims and conversion-page sections are not appropriate.

## Applied copy

- Headline: **Find the bus behind the dot.** Connects a familiar map marker with the actual vehicle and its detail view.
- Body: **Pick a vehicle number. See its last reported position, the destination on its sign, and the trip it is running.** Describes the exact information available, including the reporting-time limitation.
- Main action: **Find a vehicle.** Includes the rail and ferry vehicles present in the same feed.
- Scope note: **Buses, trains, and ferries. Straight from the MBTA feed.** Keeps the bus-led illustration from implying that the dataset contains only buses.
- Guide headline: **Read the feed. Know its limits.** Introduces source freshness, statuses, and scheduled trips without promising operational certainty.
- Illustration: **Illustration · not a live vehicle.** Distinguishes the custom animation from actual fleet telemetry.

## Alternatives considered

1. **Pick a number. Follow a vehicle.** Clear action, but weaker connection to the custom bus artwork.
2. **Where did that bus last check in?** Accurately foregrounds source freshness; too long for the intended composition.
3. **Find the bus behind the dot.** Selected for the visual-to-product connection; the supporting copy states exactly what is fetched.

CTA alternative: **Open the fleet** is accurate, but **Find a vehicle** describes the user's task more directly.

Self-check: removed generic city-motion slogans, story-language filler, repeated oversized wordmarks, and vague confidence claims. No invented metrics, testimonials, latency promises, or arrival predictions were added. Status descriptions remain consistent with the source API.
